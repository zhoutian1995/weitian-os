人在外面，家里 Agent 挂了：Tailscale + SSH + tmux 远程救场

小天说FDE 2026-03-13 发布 约 6 分钟读完
TL;DR · 一分钟版本

手机突然收到监控报警：家里的 Agent 挂了，人却在外面吃饭。Tailscale + SSH + tmux 的组合：不需要公网 IP，也不用单独买 VPS，手机连进 tailnet 打开 Mac 上的 tmux 会话，就能查看 Claude Code 输出、继续排查或重启任务。关键不是远程桌面，而是保住终端现场。

有次我在外面吃饭，手机突然收到监控报警：家里的“小龙虾”挂了。

人在外面，日志在 Mac 上。等赶回家再处理，最好的排错现场可能已经丢了。

我后来把 Tailscale、SSH 和 tmux 组合起来。手机连进自己的 tailnet，通过 SSH 打开 Mac 上的 tmux 会话，就能查看 Claude Code 的输出、继续排查或重启任务。

这套方案不需要公网 IP，也不用单独买 VPS。关键不是“远程桌面”，而是保住终端现场。

为什么我没有只用 Claude Code 的远程功能

当时我试过 Claude Code 的 /rc。它很方便，但在我所处的网络环境里，连接偶尔不稳定。救急时最怕的不是功能少，而是连接到一半断掉。

所以我准备了一条更通用的路径：

手机上的 SSH 客户端
        ↓
Tailscale 加密网络
        ↓
家里的 Mac
        ↓
tmux 持久会话
        ↓
Claude Code / 日志 / 重启命令

Tailscale 会尽量建立设备间的直接连接；网络条件不允许时，也可能通过 DERP 中继。更准确的说法是“优先点对点、全程端到端加密”，不是绝对不经过任何中继。连接类型可以参考 Tailscale 官方说明。

三个工具分别解决什么

工具作用
Tailscale让手机和 Mac 像在同一个私有网络里，不暴露公网 SSH 端口
SSH从手机进入 Mac 的终端
tmux让任务和会话留在 Mac 上，手机断线后仍继续运行

tmux 是这套方案的关键。手机只是窗口，真正的会话一直在 Mac 上。切换 Wi-Fi、关闭 App，甚至短时断网，都不会让排查任务跟着消失。

配置前先把安全边界说清楚

远程 SSH 很方便，也意味着手机一旦丢失，风险会变大。

我的建议是：

  • 优先使用 SSH 密钥，不把 Mac 登录密码写进提示词、脚本或聊天记录；
  • 只允许自己的 Tailscale 设备访问，不要把 22 端口暴露到公网；
  • 给手机设置系统锁和生物识别，SSH 私钥放在受保护的钥匙库；
  • 限制可登录用户，确认密钥登录可用后再关闭密码认证；
  • 对能操作生产环境的 Agent 再加一层确认，不让远程连接等于无限权限。

原公众号文章里有一段“把用户名和密码交给 AI 配置”的提示词。这个做法现在不保留。密码应该由本人交互输入，或者改用密钥认证。

第一步：Mac 端准备

开启远程登录

在 macOS 中打开：

系统设置 → 通用 → 共享 → 远程登录

只允许需要的用户登录，不要默认开放给所有本机账户。

安装 tmux

brew install tmux

安装并登录 Tailscale

Mac 和手机加入同一个 tailnet。登录后记下 Mac 的 Tailscale 地址，通常是 100.x.x.x，也可以使用 MagicDNS 设备名。

避免任务因休眠中断

长期运行的 Mac mini 可以在系统设置里调整休眠策略。临时排查时也可以使用：

caffeinate -i

不要把 caffeinate 当成永久运维方案。真正长期运行的服务还需要开机自启、健康检查和故障恢复。

第二步：手机端准备

手机安装 Tailscale 和一个 SSH 客户端。原文使用的是 Termius，其他支持密钥和主机校验的客户端也可以。

连接信息大致如下：

字段内容
AddressMac 的 Tailscale IP 或 MagicDNS 名称
Port22
Username允许远程登录的 Mac 用户名
AuthenticationSSH 私钥，优先于密码

第一次连接时认真核对主机指纹，不要看到提示就直接点接受。

第三步：把任务放进 tmux

首次创建会话：

tmux new -s lobster

进入会话后再启动 Claude Code 或你的 Agent：

claude

断开后重新连接：

tmux attach -t lobster

如果有多个会话，先查看列表：

tmux ls

真出故障时怎么做

我现在的处理顺序很简单：

  • 1. 手机上打开 Tailscale，确认已连接；
  • 2. 用 SSH 客户端进入 Mac；
  • 3. tmux attach -t lobster 恢复现场；
  • 4. 先看日志和进程状态，不急着重启；
  • 5. 让 Claude Code 给出排查建议，人确认后再执行修改；
  • 6. 修复后验证服务、告警和关键任务是否恢复。

这比远程桌面更适合终端型 Agent。屏幕小没关系，最重要的日志和命令都在会话里。

这套方案解决不了什么

如果 Mac 已经关机、系统卡死、路由器断网或 Tailscale 本身没有启动，手机 SSH 也救不了。要覆盖这些情况，还需要智能插座、带外管理、备用网络或自动拉起机制。

所以远程 SSH 是救场工具，不是完整的高可用方案。

写在最后

我喜欢这套组合，不是因为它多高级，而是因为每个工具只做一件事：Tailscale 负责连接，SSH 负责进入，tmux 负责保留现场。

技术真正好用的时候，应该让人少赶一次路，少丢一次排错现场。

人在外面，手机能安全地回到家里的终端，这就够了。

常见问题

怎么远程救活家里的 Agent？
手机装 SSH 客户端，通过 Tailscale 组成的加密网络连回家里 Mac，attach 到 tmux 会话查看 Claude Code 的输出并继续操作。全程不需要公网 IP，也不用买 VPS。
为什么要用 tmux？
tmux 让终端会话在断线后依然存活。救急时最怕连接到一半断掉——会话在 tmux 里，重连 attach 就能回到现场，排错上下文不丢。

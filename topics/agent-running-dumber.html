为什么你的 AI Agent 越跑越笨？一篇论文说清了

小天说FDE 2026-06-02 发布 约 8 分钟读完
TL;DR · 一分钟版本

给 Agent 加更多工具、跑更多轮、给更多 token，结果反而不如直接问一次？哈工大的一篇论文用严谨实验证明了这件事，并给出反直觉结论：Agent 的性能不取决于你花了多少 token，而取决于这些 token 产生了多少「有效反馈」。

你有没有这种感觉——给 AI Agent 加了更多工具、让它多跑几轮、给了更多 token，结果反而不如直接问一次？

我最近读了一篇哈工大的最新论文，它用严谨的实验证明了这件事，而且给出了一个很反直觉的结论：

Agent 的性能，不取决于你花了多少 token，而取决于这些 token 产生了多少「有效反馈」。

01 先说结论

这篇论文提出了一个叫 EFC（Effective Feedback Compute，有效反馈计算量） 的概念。

简单说就是：不是所有 Agent 跟环境交互产生的反馈都有用。一个反馈只有在同时满足四个条件时才算「有效」：

◆ 信息量大（不是废话）

◆ 来源可靠（不是瞎编的）

◆ 不重复（之前没听过）

◆ 能影响后续决策（Agent 真的用上了）

四个条件是乘法关系——任何一个维度挂零，这条反馈就等于白给。

打个比方：开会的时候，一个人说了十分钟，但说的全是已经知道的信息（不重复性=0），那这十分钟就是浪费。另一个人只说了一句关键信息，而且大家听进去了、改变了方案——这才是有效反馈。

Agent 也一样。

02 最狠的实验：同花 1000 token，成功率差 3 倍

论文里有一个实验特别精彩。

研究者控制了完全相同的 token 预算、相同的工具调用次数、相同的耗时，唯一不同的就是反馈的质量。

结果：

低质量反馈组：成功率 27%

高质量反馈组：成功率 90%

同样的计算量，差距超过 3 倍。

这说明什么？ Agent 不笨，是反馈喂错了。

就像给一个人看 100 条垃圾信息和给一个人看 10 条精准信息，后者效率远高于前者。

03 传统指标为什么不行？

我们平时评估 Agent 效率，习惯看这些：

• 用了多少 token

• 调了多少次工具

• 跑了多长时间

• 花了多少钱

论文测了所有这些指标，用 R² 来衡量它们预测 Agent 成功率的能力（越接近 1 越准）：

Token 数 → 0.33

工具调用次数 → 0.42

耗时 → 0.37

总成本 → 0.38

EFC → 0.94

EFC / 任务难度 → 0.99

Token 数只能解释 33% 的性能变化，而 EFC 能解释 94%——如果再考虑任务本身的难度，可以到 99%。

更夸张的是在真实场景（混合了代码、终端、Bug 修复任务）里，传统指标全部负分——比瞎猜还差。EFC 依然稳在 0.92。

04 七种 Agent，谁是赢家？

论文设计了 7 种不同的 Agent 框架，从简单到复杂：

H0：直接回答，不调工具

H1：加了检查清单

H2：能选择性地调用工具

H3：有记忆，不重复犯错

H4：预算拉满，但路由差、验证弱、记忆烂

H5：完整闭环：路由 + 验证 + 记忆

H6：深度闭环，更强的反馈机制

H4 是最关键的对照。

如果性能由计算量决定，H4 预算最高，应该最强。但实际上 H4 表现很差——因为它虽然花了很多 token，但产生的反馈质量低、重复多、没被记住。

砸钱不能解决所有问题，这句话在 Agent 时代依然成立。

05 三个实操启示

读完这篇论文，我觉得对做 Agent 的人有三条直接可用的建议：

  • 1. 优化路由比堆预算重要

路由质量对效率的提升最大（+0.28）。Agent 能不能选对工具、问对问题，比多调几次工具重要得多。

  • 2. 加强验证，少走弯路

验证强度排第二（+0.22）。Agent 每做一步，如果能有可靠的方式验证对不对，就能避免把错误往下传。

  • 3. 管好记忆，别重复犯错

记忆保真排第三（+0.20）。Agent 能不能记住之前试过什么、哪里失败了，直接影响后续决策的效率。

还有一个容易被忽略的发现：没有万能最优的 Agent 框架。论文发现在代码任务上 H5/H6 最强，但在 Bug 修复任务上反而简单的 H0/H3 更好。不同任务需要不同的设计。

06 写在最后

这篇论文的标题叫「Scaling Laws for Agent Harnesses via Effective Feedback Compute」，来自哈尔滨工业大学，2026 年 5 月发布。

它改变了我对 Agent 优化的认知：不是花更多计算，而是让每一份计算都变成有用的反馈。

就像高效的团队不是因为加班多，而是因为每次沟通都在推进事情。

Agent 也一样——让它说的每一句话都有信息量、有依据、不重复、且能指导下一步行动。

这才是 Agent 真正的 scaling law。

论文链接：https://arxiv.org/abs/2605.29682

常见问题

为什么 Agent 越跑越笨？
无效反馈在多轮执行中不断累积：错误的中间结果被后续步骤放大，token 花得越多，噪声越大。性能瓶颈在反馈质量，不在资源投入。
什么是有效反馈？
能修正下一步决策的信号：明确的成功/失败判定、可验证的中间结果。没有验收机制的轮次越多，Agent 偏得越远。
